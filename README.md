# Multiview — багатовекторний дайджест новин

Мета: для кожної гарячої теми показувати, як її подають різні видання світу (з посиланнями, позначками про власника/фінансування й попередженнями), українською та англійською. Безкоштовно для автора й читачів.

**Етап 1 (цей архів):** збір RSS → групування в події → рейтинг (година / день / тиждень) → чернетка. **Нічого нікуди не публікує.** Без зовнішніх залежностей: потрібен лише Python 3.9+.

## Запуск (macOS, Термінал)
```
cd ~/Desktop && unzip -o ~/Downloads/multiview-v2.zip -d multiview && cd multiview
python3 -m unittest discover -s tests
python3 -m digest.run --window day --top 8
```
- Перший запуск покаже рядки `✗` для стрічок, які не відповіли (адреси я не міг перевірити з сервера розробки). Надішліть мені ці рядки — виправлю.
- Режими: `--window hour` (останні 3 год), `day` (24 год), `week` (7 днів). `--out draft.md` зберігає у файл.
- Перевірка без інтернету: `python3 -m digest.run --fixtures tests/fixtures --now 2026-11-11T12:00 --window week`

## Джерела
Файл `sources.json`: кожне видання має країну, тип (суспільне / державне / комерційне / некомерційне / незалежне в екзилі) та позначку обережності. Російські видання: лише незалежні в екзилі, з позначкою, що їхнє фінансування потребує перевірки. Державні російські медіа не включено.

## Відомі обмеження етапу 1
- Групування грубе (слова заголовків), працює переважно для англомовних стрічок. Для української/російської й міжмовного групування буде потрібен вектор-ембединг (Gemini, безкоштовно в межах ліміту).
- Reuters і AP не мають офіційних безкоштовних RSS: поки їх немає.
- Немає ШІ-синтезу, перекладу й публікації в Telegram: це наступні етапи.

## Етап 2: ШІ-синтез і дописи UA/EN (чернетки, без публікації)
1. Створіть ключ у aistudio.google.com (іконка ключа). **Нікому його не показуйте.**
2. Скопіюйте ключ (Cmd+C) і виконайте одним рядком (ключ береться з буфера обміну, його не видно й не друкується):
   `printf 'GEMINI_API_KEY=' > ~/.multiview.env && pbpaste >> ~/.multiview.env && chmod 600 ~/.multiview.env`
3. Перевірка: `python3 -m digest.run --list-models` (покаже назви моделей, доступних вашому ключу).
4. Запуск: `python3 -m digest.run --window day --synth --top 4 --candidates 6`
   Чернетки з'являються в `drafts/…/NN-uk.html` та `NN-en.html` (формат Telegram HTML). Кожна подія = 1 запит до моделі; `--candidates` обмежує їх кількість (безкоштовний ліміт на день невеликий). Іншу модель: `--model назва`.
5. Без ключа можна подивитись, що піде в модель: `python3 -m digest.run --window day --dry-prompt`.
Модель бачить лише заголовки й анонси з RSS (не повні статті) і не має права додавати факти. Кожне її твердження має супроводжуватись дослівною цитатою з тексту відповідного видання; програма перевіряє цитату, а твердження без неї відкидає (у виводі: «відкинуто непідтверджених тверджень: N»); посилання беруться з наших даних, а не від моделі. Модель також оцінює важливість і регіон: культура/спорт відкидаються (прапор `--include-soft`), з одного регіону не більше 3 подій (`--max-per-region`).

## Наступні етапи
2. ✅ Синтез і переклад UA/EN (чернетки). Ще не зроблено: ембединги для точнішого групування, чернетки в приватному чаті з ботом.
3. Публікація в два Telegram-канали (токен бота зберігається в секретах, не в коді).
4. Автозапуск за розкладом (GitHub Actions, безкоштовно) і оновлення постів.

## v3.0
- Ілюстрації: якщо в RSS видання є картинка, Telegram показує її над постом (прев'ю статті з назвою видання). Джерела з обережністю/держфінансуванням для цього не використовуються.
- Заголовок ≤ 90 симв. без крапки, числа в ньому звіряються з текстами; один рядок контексту (з цитатою-доказом).
- Більше постів: `--slot morning` дає до 10 (2 повні на головній моделі + решта короткі пакетами). Повторів немає: `state/published.json` пам'ятає опубліковане 3 доби.
- `--publish` надсилає пости в канал (`TELEGRAM_CHAT_ID`) і записує їх у пам'ять.
- Зупинка: у чаті з ботом напишіть `/stop` (і `/start`, `/status`). Потрібен `TELEGRAM_OWNER_ID` у ~/.multiview.env. Локально: `python3 -m digest.control --stop|--start|--status`.

- `.github/workflows/`: `radar-generate.yml` (розклад: 10:30, 14:00, 19:00, 22:30 за Києвом взимку) і `radar-drip.yml` (кожні 30 хв). Секрети репозиторію: GEMINI_API_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, TELEGRAM_OWNER_ID. Стан (`state/`) комітиться назад у репозиторій.

## v3.4
- `--min-importance` (за замовчуванням 6): події з нижчою оцінкою важливості не потрапляють у канал.
- `--polish N` (за замовчуванням 2): головна модель літературно вичитує N найважливіших постів запуску (лише мова; числа мають збігатися, інакше лишається оригінал; результат кешується; якщо ліміт головної моделі вичерпано — пропускається).

## v4.3: формат і подача
- У постах більше немає «Станом на …» і підпису про RSS (його варто мати в описі каналу): рядок «Пишуть N видань» з правильною множиною.
- Скасовано «короткий режим»: усі пости мають 2–3 пункти «що відомо» й контекст; модель має писати так, щоб пост був самодостатнім без переходу за посиланням.
- Безперервний цикл сам генерує невелику свіжу порцію щогодини (`--gen-every 60`, `digest/gen.py`, `--slot hourly`, лише запасна модель; вночі рідше; не генерує, якщо в черзі вже ≥ 5). Cron-слоти лишаються.
- Інтервал між постами 15–40 хв (було до 60), термін життя допису в черзі 8 год (було 13).
- Відбір ураховує українську аудиторію (`REGION_BONUS` у `digest/synth.py`): Україна +2, ЄС +0,8, США +0,3, Азія/Африка/Латинська Америка нижче.
- Із переліку «Також пишуть» прибрано ⚠️ (природа видання лишається в рядках «Погляди видань»).

## v4.6 — опитування з «історіями дня»
- Щоденне опитування: 6 постійних тем (країни й регіони) + до 3 «історій дня» (заголовки постів, що вийшли за останню добу, без повторів за змістом). Порядок варіантів перемішується щодня інакше. - «Топ-рейтинг» може бути і про країну/регіон, і про конкретну історію дня (`kind: story`): стрічки відбираються за збереженими посиланнями й словами заголовка. Історії з опитувань старших за 2 доби не беруться.
- «Достатньо голосів» (`min_votes`) тепер рахується за людьми (`total_voter_count`), а не за кількістю обраних варіантів.
